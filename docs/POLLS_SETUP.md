# Голосования в Twitch: первое подключение

Код добавляет вкладку **Голосования** в `/admin` и прозрачный OBS-виджет `/widget/poll`. Это собственные голосования StreamQueue по сообщениям чата; Twitch Affiliate/Partner не требуется. Встроенные платные голоса Twitch и Channel Points не используются.

## 1. Подготовить базу Supabase

Открой нужный проект Supabase → **SQL Editor** → **New query**. Вставь содержимое файла `supabase/migrations/202610290001_stream_polls.sql` целиком и нажми **Run**. Это одноразовая миграция с транзакцией: создаются только новые таблицы и функции, музыкальная очередь не изменяется. Не запускай ее повторно после успешного выполнения.

Проверка без изменения данных:

```sql
select to_regclass('public.stream_polls');
select public.stream_poll_state(true);
```

Новые таблицы закрыты для анонимного клиента и обычных Supabase-пользователей. Только сервер с `SUPABASE_SERVICE_ROLE_KEY` может читать/менять их. Не выключай RLS и не публикуй этот ключ. Публичный виджет получает через собственный API только сводные результаты.

## 2. Зарегистрировать приложение Twitch

1. Зайди под своим аккаунтом стримера в [Twitch Developer Console](https://dev.twitch.tv/console/apps). Подтверди email и включи двухфакторную аутентификацию, если Twitch попросит.
2. Открой **Applications → Register Your Application**.
3. **Name:** например, `StreamQueue — твой ник`. Название должно быть уникальным.
4. **OAuth Redirect URLs:** добавь ровно этот адрес кнопкой **Add**:

   ```text
   https://www.wewannaflyanyway-music.ru/api/twitch/oauth/callback
   ```

5. **Category:** `Chat Bot`. Если есть выбор типа клиента — **Confidential**, поскольку секрет хранится на сервере.
6. Создай приложение. Нажми **Manage**, скопируй **Client ID**, затем нажми **New Secret** и сохрани **Client Secret**.

Секрет не нужно присылать в чат, вводить в форму StreamQueue или добавлять с префиксом `NEXT_PUBLIC_`.

Официальная инструкция: [Register Your App](https://dev.twitch.tv/docs/authentication/register-app/).

## 3. Добавить переменные в Vercel и сделать деплой

В проекте StreamQueue открой **Settings → Environment Variables**. Для окружения **Production** добавь:

| Переменная | Значение |
| --- | --- |
| `APP_URL` | `https://www.wewannaflyanyway-music.ru` |
| `TWITCH_CLIENT_ID` | Client ID из Twitch |
| `TWITCH_CLIENT_SECRET` | Client Secret из Twitch, пометить как sensitive |

Существующие переменные Spotify, Supabase и `ADMIN_PIN` сохрани. Выполни production-деплой кода вместе с новыми переменными. Изменение переменных само по себе уже запущенный deployment не обновляет.

Для другого домена одновременно поменяй `APP_URL` и Redirect URL в Twitch. Webhook должен быть доступен Twitch по HTTPS на порту 443 и без дополнительной страницы авторизации/Deployment Protection. Он защищен подписью Twitch. Предпросмотр OBS работает локально, но реальный EventSub не доставляет события на `localhost`.

## 4. Подключить канал

1. Открой именно [админку на основном домене](https://www.wewannaflyanyway-music.ru/admin), введи PIN и выбери **Голосования**.
2. Нажми **Подключить Twitch** и подтверди доступ под аккаунтом своего канала. Отдельный аккаунт бота не требуется.
3. Приложение запрашивает `user:read:chat`, `user:bot`, `channel:bot` — для чтения чата через серверный EventSub. Отправка сообщений и управление твоим Twitch-аккаунтом не реализованы.
4. Вернувшись, нажми **Проверить**. Должен появиться статус **Подключен** и твой логин. Начало каждого голосования тоже проверяет состояние подписки у Twitch.

Если доступ отозван в Twitch Connections, повтори подключение. После смены Client Secret или домена обнови переменные, сделай деплой и подключи канал повторно. Приложение пересоздает подписку при смене ключа, поскольку Twitch сохраняет старый секрет у существующего webhook.

## 5. Добавить виджет в OBS и провести проверку

1. Добавь **Источник → Браузер**. Адрес:

   ```text
   https://www.wewannaflyanyway-music.ru/widget/poll
   ```

2. Размер источника: **1000 × 1000**. Ширина самой карточки настраивается в админке. Виджет прозрачный; при отсутствии голосования он ничего не показывает.
3. Для проверки оформления до запуска можно временно использовать `/widget/poll?preview=1`. Там всегда демонстрационный опрос; **для настоящего стрима убери `?preview=1`**.
4. В админке добавь вопрос и 2–6 вариантов, выбери время и формат, нажми **Начать голосование**.
5. Со второго Twitch-аккаунта напиши в чат `1`, затем `2`: при разрешенной смене выбора должен остаться ровно один голос за второй вариант. Повтор `2` не добавляет голосов. В командном режиме пиши `!vote 2`.
6. Проверь ручное завершение, добавление 30 секунд, ничью, автоматическое завершение и скрытие итогов. Результаты по умолчанию видны 15 секунд; 0 в настройке показа означает до следующего опроса. Кнопка **Скрыть виджет** скрывает его вручную; новый опрос снова включает видимость.

Сообщение с другим текстом (`я за 2`, `22`, `2!`) не является голосом. Один аккаунт Twitch дает один голос; защита от нескольких разных аккаунтов одного человека не реализована. Текст сообщений целиком не сохраняется: в базе только ID участника, выбранный вариант, ID и время сообщения. Удаление сообщения модератором не отменяет уже принятый голос.

Сбор голосов идет на сервере независимо от открытой админки и OBS. Наступление конца проверяется базой при каждом голосе/чтении; отдельный таймер процесса или cron не нужен. Виджет обновляет данные примерно раз в 1,5 секунды, админка — раз в 2,5 секунды. При сбое связи отображается предупреждение и идет повторное подключение. Таймер основан на времени сервера.

Отсутствие сообщений в тихом чате не означает отключение: EventSub не присылает heartbeat. Для актуального статуса служит кнопка **Проверить**, время последней проверки и последнего сообщения. Возможны задержки/потери при недоступности сервера и отозванных разрешениях; приложение не может гарантировать доставку каждого сообщения Twitch. Каждый доставленный chat event создает серверный запрос; при большом чате учитывай лимиты Vercel и Supabase.

## Проверки разработчика

```powershell
npm run test:polls
npm run build
npm exec -- eslint src/lib/polls src/components/polls src/app/api/polls src/app/api/twitch/oauth src/app/api/twitch/eventsub src/app/widget/poll tests/polls.test.ts
```

Тесты выполняют настоящий SQL миграции в изолированном PostgreSQL через PGlite: права доступа, черновики, запуск, повторные/запоздавшие голоса, смена выбора, таймер, завершение. Они не подключаются к production-базе. Подпись webhook и публичное скрытие результатов проверяются отдельно. Живая авторизация, доставка сообщений Twitch и вывод в OBS требуют настройки выше и проверки на канале.

Технические источники: [Twitch EventSub webhooks](https://dev.twitch.tv/docs/eventsub/handling-webhook-events/), [Chat authentication](https://dev.twitch.tv/docs/chat/authenticating/).
