# Очередь и история стрима

## Включение после подготовки кода

1. В Supabase открой **SQL Editor**, вставь и выполни целиком [`supabase/migrations/202611010001_stream_sessions.sql`](../supabase/migrations/202611010001_stream_sessions.sql). Выполняй ее один раз; таблицы заявок и настройки сохраняются. Миграцию нужно применить **до деплоя** нового кода: он использует новые поля заявок.
   Затем один раз выполни [`supabase/migrations/202611010002_manual_offline_requests.sql`](../supabase/migrations/202611010002_manual_offline_requests.sql), которая добавляет ручное открытие заказов вне эфира.
2. Разверни новую версию сайта. Существующих `APP_URL`, `TWITCH_CLIENT_ID` и `TWITCH_CLIENT_SECRET`, настроенных для голосований, достаточно. При наличии `Deployment Protection` убедись, что Twitch может отправлять HTTPS-запросы на `/api/twitch/stream-events`.
3. В админке нажми **«Включить автоматику Twitch»**. Если канал еще не подключен, сначала открой «Голосования» → «Подключить Twitch». Приложение создаст и проверит подписки на начало и окончание эфира. При ошибке подписки проверь доступность сайта и нажми кнопку повторно.
4. Проверь настройки ручного приема заявок. При включении автоматика сохраняет текущую ручную паузу: если прием уже выключен, включи его вручную во время стрима, когда будешь готов.

Когда Twitch сообщает об окончании, прием закрывается. Если эфир вернулся не позднее 30 минут, сервис сохраняет ту же историю. После более длинного перерыва создается новый стрим; оставшиеся на модерации заявки предыдущего помещаются в архив. Ручное отключение приема имеет приоритет над автоматическим включением. Если подписка Twitch отозвана, прием закрывается, а в админке появляется кнопка восстановления.

Вне эфира прием можно открыть вручную кнопкой в админке. Эти заказы появятся в очереди и будут отнесены к следующему стриму; при очередном завершении эфира прием снова закроется автоматически. История заказов на главной показывается во время эфира.

При пропущенном уведомлении состояние дополнительно сверяется с Twitch при открытии страницы и заказе; если Twitch недоступен во время необходимой проверки, новая заявка не добавляется. События могут приходить с задержкой. Если уведомления пропущены и Twitch не сообщает точное время обрыва, границу 30 минут не всегда возможно восстановить точно.

История делится по стримам без удаления старых записей: нужный период выбирается в админке во вкладке «История стрима». Очистка текущей истории в автоматическом режиме скрывает записи, сохраняя сведения для очереди. Заявки, которые уже находятся в плеере Spotify, продолжают находиться там и после смены стрима; при необходимости их нужно убрать в самом Spotify.

## Команда Nightbot

Для перехода на команды с подтверждённой Twitch-личностью и закрытие прямого доступа к базе см. [инструкцию по обновлению](HARDENING_SETUP.md). После включения нового режима вместо настройки Nightbot ниже команды обрабатывает само приложение.

Создай команду, например `!очередь`, с таким полем Message:

```text
$(urlfetch https://wewannaflyanyway-music.vercel.app/api/bot/position?user=$(user))
```

Команда относится к последней активной заявке пользователя. Она сообщает количество треков **перед ней в очереди Spotify**; текущий трек считается отдельно. Заявка на модерации еще не имеет надежной позиции. При нескольких одинаковых треках Spotify не предоставляет идентификатор заявки, поэтому в спорном случае бот попросит проверить очередь позже.

Главная показывает текущий трек, заказанные треки из очереди Spotify и отдельный список заявок на модерации. Списки длиннее пяти записей можно развернуть. Между заказами в плеере могут находиться другие треки, поэтому их номер в списке заказов не обязательно равен позиции в полной очереди Spotify. Автор заказа показывается, когда в текущем снимке нет дубликатов; неоднозначные совпадения отмечаются как возможные заказы. Сопоставление выполняется по URI трека: Spotify не сообщает ID заявки, поэтому ручное повторное добавление уже звучавшего трека после пропущенной синхронизации может сделать сопоставление неточным. Блок истории виден всегда, а записи появляются во время активного эфира и содержат одобренные заявки текущего стрима, включая те, что еще находятся в плеере.

Переходы треков отслеживаются во время запросов к странице очереди или пока открыт существующий музыкальный браузерный источник OBS. Если они оба закрыты и команда позиции не используется, отдельный трек может пройти между проверками; в таком случае полная история заказов сохранится, но его статус `played` может не обновиться. При недоступности Spotify позиции не выдумываются.

Проверки разработчика: `npm run test:stream`, `npm run test:bot-search`, `npm run build`.
